# v0.4 Technical Debt

## M18 Audit — 2026-10-13

以下均不阻塞已验收M18；不在M18中顺手重构。M19若需要接入，只做其范围内有限的只读投影，不统一或重写事务与持久化底座。

| 观察 | 现有安全边界 | 后续方向 |
|---|---|---|
| ExternalPlateContract只资格化单矩形、世界XY、已有驱动和配置范围 | Query只筛选已被M14资格化的模型，不升级未知形状／历史 | v0.4按可复用Native subtype及独立几何证据扩展；不是给特定零件增加分支 |
| 预览、dispatch、M14 preflight分别做完整原生核对 | 重复核对保护预览到执行的身份／成员／值边界，当前不能省略 | 有测量证据后考虑可验证snapshot复用；保持dispatch时重新验证与fail-closed |
| 整体观测JSON指纹包含展示及证据字段 | 无关元数据变化也可能使旧预览失效，属于保守再确认，不自动重定向 | v0.4可定义最小稳定执行身份指纹，并单独验证重命名／证据更新语义 |
| Native依赖图不等于机械设计关系；关系闭包逐目标计算 | 已知GetParents/GetChildren／Seed关系只用于选择与安全排序，不推断配合／功能；数量有界 | M19采用明确只读结构投影；v0.4再评估缓存与关系语义扩展 |
| Generic与External状态／会话各有已验收边界 | 不把Generic创建史或未知外部史强行改写为同一可编辑模型 | M19局部展示可分别适配；通用统一表示不是本轮验收前置 |
| 批准是会话内一次性对象 | 冷恢复后旧批准不能跨会话重放，需新预览／确认 | 当前是有意的安全设计；将来若需要持久批准，另行设计身份与撤销协议 |

本轮实际阻塞只有Query的浮点表示匹配缺陷，已以8 ULP边界修复并通过真实原生回归；没有借此降低几何容差或扩大特征支持。

## M19 Extension — 2026-10-13

- 保留 v0.2、Generic、External 的独立语义／会话，M19 只做 DTO 与入口适配；统一状态或事务引擎不是完成 UI 的前置。
- 局部结构图展示记录的 Native/typed input 与 declared design provenance；不将几何对齐、M15 的解析约束或固定坐标推断为通用原生可关联参数。
- 当前 UI 的 Scalar/Query 控件面向 External；Generic 参数资格可检查，构造/恢复可用。更完整的 Generic 原生编辑表单、结构义务和编辑角色编辑器可后续扩展，但不能用 UI 添加新的参数资格。
- 状态轮询有意不触发 COM；原生改变必须在正式 preflight/dispatch 中重新验证。若将来需要更高频原生观测，另行设计 STA 与资源成本，不用后台自动 native retry。

这些不是 M19 的验收缺项；没有借本轮重构 IR、Binder、求解、回滚或持久化协议。
