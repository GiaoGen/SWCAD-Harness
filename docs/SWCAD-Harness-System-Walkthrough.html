CAD Harness v0.2
系统是怎样工作的

一句话：把自然语言压缩成有限 typed CAD 意图，再由确定性关系求解、语义绑定、SOLIDWORKS 后端、transaction 与 validation 执行和维护。

面向项目作者：懂基本编程和机械 CAD，但不熟悉内部架构。所有解释以当前 production source 为准，支持范围是有限 vocabulary，不是 arbitrary CAD。

LLM 控制多少？模型决定高层 operation composition、参数和 relation，并输出 CadProgram。响应之后 parse、capability、preflight、binding、COM、rebuild、validation、rollback、state commit 都由普通 deterministic software 控制。Stepwise 每步会再问模型，但仍由 Harness 控制执行边界。

本次静态分析；未改 production/tests/benchmark；未启动 SOLIDWORKS；Native Parts created = 0。

1. 一分钟理解整个项目

Harness 不是 LLM 控鼠标、不是任意 SOLIDWORKS API 生成器、不是 giant tool list、也不是固定零件 generator。它是“计划受限、执行可核验、失败可恢复”的系统组合。

AI boundary

Intent + runtime capability + model context → structured response → typed CadProgram。Harness 一次规划整体；edit 输出一个 edit；Stepwise 一次一个 operation。

Deterministic boundary

Provider response 后：strict parse → capability validation → pure preflight → relation solve/global check → Binder → transaction → native handlers → rebuild/readback → validation → CADState commit。

3. Typed CAD IR：有限共同语言

CadProgram = version + Operations + Relations。OperationNode = Id + Kind + SemanticId + Inputs + Parameters。OperationContract 记 wire name、typed inputs、parameter range、preconditions/effects/postconditions/outputs；OperationRegistry 登记 contract。SemanticReference = semanticId + SemanticType；DesignRelation = kind/subject/reference。

当前 operation vocab：create_extrude、create_through_hole、create_blind_hole、create_linear_pattern、create_rectangular_pattern、create_circular_pattern、apply_fillet、apply_chamfer、edit_parameter。Profiles: centered_rectangle / circle。

不让 LLM 直接调 API：一个高层 CAD 操作可跨 sketch、feature、rebuild、readback 多个 COM 调用；IR 让本地检查类型、约束、能力与整体计划。Finite IR 优于 giant tool list，因为模型组合 feature-level actions；代价是新能力要配套实现和登记。

G2 fixture:\nbase: extrude semanticId=plate, rectangle 100×60, depth=8\nhole: through-hole semanticId=mounting_seed, host=plate.top_face,\n      Ø6, placement=(-30,-15)\npattern: rectangular pattern, seed=mounting_seed, 2×2,\n         spacing=60×30, directions=plate.direction_x/y\nrelations=[]
概念G2 示例意义
operation IDbase/hole/patternprogram 内节点 id
semanticIdplate/mounting_seed设计 feature identity
semantic outputplate.top_facetyped contract output
native feature/objectSolidWorks Feature/IFace2后端创建、persistent ref 定位；不等于前三种字符串
G2 fixture 用显式 placement/spacing 且 relations 为空。centered_about 是解释 solver 的同类意图，不是 fixture 原始字段。

4. RuntimeCapabilityCatalog

OperationRegistry 是 IR 能表达的 contract 集；RuntimeCapabilityCatalog 是当前 runtime/mode/session 真正可执行的 operations、profiles、edits/value ranges、relations/contracts、outputs、constraints。Planner 只看 projection，本地 Validate 再确认 operation/profile/producer references/edit target/range/relation support。IR 中定义 enum 不意味着自动可执行。

unsupported capability 在 mutation 前拒绝

5. Planner：Structured Output 不代表信任模型

Intent=目标；Capability JSON=当前可执行集合；Model context=committed state；Response schema=响应 envelope/program shape。

CadPlanner / StepwisePlanner prompt
↓
PlannerResponseSchema → ProviderSchemaCompatibility
↓
DeepSeekPlanSource / OpenAiPlanSource / ChatCompletionPlanSource
↓
provider json_schema → strict local envelope parser
↓
CadProgramJson → ProgramValidator → runtime capability validation
↓
pure preflight → execute only after pass

Provider schema 约束形状，不证明语义、能力、几何组合或 rebuild 正确。Parser 检重复 keys/depth/size/envelope；IR validator 检 contract；Catalog 检 runtime；preflight 检 merged plan。M10A/B schema/contract 问题是工程案例；formal M10 schema audits PASS，但不会跳过本地验证。

Tests 与 production 的界限

6. Harness mode vs Stepwise mode

Harness

Intent → 一个完整 CadProgram → execute。

Stepwise

Intent → 选一 op → execute/commit → observe committed state → 再选一 op → … → complete。

共享 IR、capabilities、provider、relation/backend、edit backend、final oracle。不同是决策粒度。SolidWorksStepwiseRuntime observation 实含 revision、committedOperationIds、committedSemanticIds、committedOperations、healthySemanticOutputs、entities(type/owner/health/geometry)。这些来自真实 committed snapshot，不含 future operation/IDs/relation，所以无 future oracle。

Formal M10 公平点：两模式同 intents、DeepSeek/model settings、runtime vocabulary、backend、validator；Stepwise 只获每步已提交状态。

Source: src/CadHarness.Planning/StepwisePlanner.cs, StepwiseAgent.cs, src/CadHarness.SolidWorks/SolidWorksStepwiseRuntime.cs.
Evidence: formal observation-*.json.

8. Semantic Entity / Persistent Identity

base_plate.top_face 是 Harness 的 typed semantic output，不是 Face2。CADState 将其映射至 persistent reference bytes；当前 document 上通过 GetObjectByPersistReference3 解析成 native object。

semantic id: base_plate.top_face
CADState mapping ↓
NativePersistentReference: Base64 payload + health
current document resolve ↓
native IFace2 / IFeature
  • semantic identity=设计概念名；native identity=persistent reference；geometric description=筛选/校验特征，不是身份。
  • FeatureNode / SemanticEntityNode 保存 id/kind/type/owner/reference/health，可选 geometry。
  • ParameterNode / ParameterBinding 保存 editable value 与 owner/EditableParameter 绑定。
  • 修改后重解析引用；stale/deleted/suppressed 拒绝使用。支持范围内可维持 identity，不保证任意 topology 变化后还能找到概念上“同一个面”。

SemanticStateCapture 从 document 重新读状态。CADState 是 semantic state，不是 SolidWorks document 完整复制。

Source: src/CadHarness.State/CadState.cs, src/CadHarness.SolidWorks/PersistentReferenceAdapter.cs, SemanticStateCapture.cs, DocumentIdentityAdapter.cs.

Edit planner 输出一个 EditParameter IR，指明 target/EditableParameter/typed value；ParameterBinding 找 owner；ParameterMutationRegistry dispatch；TransactionalParameterBackend 做 preflight、checkpoint、native edit、rebuild/readback、ChangeSet、DirtySet、validation 与 commit。无需重建整个 program；自然语言 edit 规划仍可能调用 LLM。

↓

13. Transaction system

数据库 transaction 是类比；SolidWorks document 本身不是数据库。真实流程：preflight → NativeConstructionCheckpoint / edit rollback capture → mutation → rebuild → postconditions → final validation → StageState → atomic store commit。

preflight → capture rollback → native mutation → rebuild → validate → commit last
失败：mutation starts → rebuild/validation fails → rollback → rebuild restored model → validate restored state → DO NOT COMMIT CADState。纯 preflight 在 mutation 前失败，不需要 rollback；restore validation 失败则 invalidates session。

MutationTransaction 编排阶段；backend 实现 native mechanics；AtomicStateStore 只保存已验证 state。commit 最后可避免 semantic state 指向失败/已回滚的 native object。

Source: src/CadHarness.State/MutationTransaction.cs, AtomicStateStore.cs, src/CadHarness.SolidWorks/TransactionalConstructionBackend.cs, TransactionalParameterBackend.cs, NativeConstructionCheckpoint.cs.

14. ChangeSet / DirtySet / Incremental Validation

ChangeSet 记录 changed features/parameters、可能失效 entities、新建 IDs。DirtySet.Expand 从 changed root 与 parameter binding 沿 graph/relation 展开 downstream features、owned entities、relations。G2 thickness 8→10 影响 extrusion depth 及依赖的 face/frame/hole/pattern；真实 dirty set 以 ChangeSet 和 graph 为准。

局部 edit + 健康 refs 可 targeted validation；NewModelFinalization、HighRiskTopology、Recovery、ReferenceReresolution、StateDriftSuspicion、ExplicitFullValidate、FaultInjection、Rollback 等 reason 升级 full validation。

M10 未证明 incremental validation 更快：targeted transaction validation 后又跑相同 full correctness oracle。
Source: src/CadHarness.State/IncrementalValidation.cs, DependencyGraph.cs, MutationTransaction.cs; ChangeSet/DirtySet.Expand/ValidationScope.Select.
